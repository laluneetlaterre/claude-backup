# nouhin-pdf ── お客様納品PDFの作成／お客様Vaultの作成

納品セットの原則（[[納品セット運用テンプレート_v1]]）：**PDF＝表玄関（届いた感・改変されない・初心者が必ず開ける）／md＝育つ種（AI第二の脳へ続く）**。正本は常にObsidianのmd。PDFはそのお客様向けの「一冊の本」として仕上げる。

md納品のタイミングは**本商品（Vault構築）移行時**（2026-07-18改訂）。体験セッションの納品はPDFのみでよい。ただし体験セッション**当日に画面共有で使うお客様専用Vault**（下記0.）は別物で、これは体験セッション時点から必要——お客様に渡すファイルの話ではなく、講師が当日操作する実演環境だから。

## ワークフロー

### 0. お客様Vaultを作成する（`obsidian_customer/`、初回のみ）

体験セッション当日に画面共有しながら使う、お客様専用のObsidian Vault一式を作る。トリガー：「○○さまのvault作って」「お客様Vault作成」、または鑑定書生成が終わったタイミングでMieyから作成依頼があったとき。

- **規約の正本**：`obsidian_customer/README_お客様Vault運用.md`。命名規則・フォルダ構成・思想はここが真実の源。迷ったら先にこれを読む。
- **雛形**：既存のお客様Vault（例：`obsidian_customer/akiko_sama/`）の構造をそのまま踏襲する。以下は個人情報を含まない共通テンプレートなので、既存Vaultからコピーしてよい：
  - `CLAUDE.md`（AI第二の脳Vaultスキーマ。全お客様共通）
  - `原文/対話ログ/README.md`
  - `テンプレート/daily-note.md`
  - `wiki/!_ウィキってなあに.md`
  - `wiki/concepts/llm-wiki-guide.md`
- **`.obsidian/` はコピーしない**。既存Vaultのworkspace.jsonにはそのお客様のファイル名の開閉履歴が残っており、そのままコピーすると別のお客様の名前が新Vaultに紛れ込む。空のままにしておけば、Obsidianを開いたときに自動生成される。
- **鑑定書3枚を配置**：`03_講師運用/お客様別（非公開）/<顧客ID>/` で `kanteisho` スキルが生成した3ファイルを `原文/鑑定書/` へコピー。
  - **frontmatterはこの時点で書き換える**。講師フォルダ側のfrontmatter（`type: kanteisho`／`generated-by: Codex`等）は内部管理用で、お客様が読むVaultにそのまま出すと講師ツールの裏側が見えてしまう。既存Vault（例：`akiko_sama/原文/鑑定書/`）と同じお客様向けスキーマ（`type: 鑑定書`／`種類`／`対象`／生年月日・タイプ等の要点のみ）に詰め替える。本文は変更しない。
- **`wiki/天命の地図_<顧客ID>.md` を作成**：`03_講師運用/お客様別（非公開）/<顧客ID>/天命の地図_<顧客ID>_事前版.md`（講師の保険版）をもとに、`sources`・原典セクションのリンクを `原文/鑑定書/` パスへ調整して配置する。中身（仮説・問い）は変えない。ステータスは「たたき台（セッション当日に本人と一緒に育てる）」に。
- **`wiki/index.md`・`wiki/log.md` を新規作成**：既存Vaultの同ファイルを土台に、顧客ID・日付を置き換えて作る。
- 既存のVaultがすでにあれば作り直さない。中身の変更はMiey確認。

### 1. 対象ファイルを特定する

- お客様のDriveフォルダ（ローカルマウント）を最初に見る：
  `~/Library/CloudStorage/GoogleDrive-hydeistpunk10ve@gmail.com/マイドライブ/WORK/Cafetalk/<お客様名>/`
- 見つからなければ `find ~/Library/CloudStorage/GoogleDrive-*/ -maxdepth 5 -type d -iname "*<お客様名>*"` で探す。それでも曖昧ならMieyに確認する（推測で別のお客様のフォルダに書き込まない）。
- **PDF化する対象**：フォルダ内の `.md` のうち、お客様向け納品物（鑑定書◯種・天命の地図・対話ログ・質問の見本帳・命式プロフィール文）。同名`.pdf`が既にあっても、mdが新しければ作り直してよい（正本はmd）。
- **PDF化しない**：講師用メモ（セッション準備・事前版など）。そもそもお客様フォルダに講師用ファイルを見つけたら、PDF化せずMieyに報告する。

**共通ファイルと固有ファイルで、Drive上の名前を変える**（2026-07-16 Miey指定）：

| 種類 | 例 | Drive上のファイル名 |
|---|---|---|
| **お客様固有**（その人だけの中身） | 鑑定書・天命の地図・対話ログ・命式プロフィール文 | `四柱推命鑑定書_<お客様名>.pdf` のように名前入り |
| **全お客様共通**（中身が同じ配布物） | 質問の見本帳・四柱推命辞典 | `質問の見本帳.pdf` のように**名前を入れない** |

共通ファイルに個人名を付けると「その人専用」に見えて誤解を生む。中身が万人共通なら名前なしが正しい。

### 2. 変換する

バンドルスクリプトを使う（毎回書かない）：

```bash
python3 ~/.claude/skills/nouhin-pdf/scripts/md2pdf.py "<ファイル1.md>" "<ファイル2.md>" ...
```

**文書の性格でスタイルを使い分ける**（2026-07-16 追加）：

| 文書 | オプション | 理由 |
|---|---|---|
| 鑑定書・天命の地図 | なし（デフォルト） | 1つずつ味わって通読する文書。行間ゆったりで読ませる |
| 質問の見本帳・辞典 | `--compact` を付ける | ざっと見渡して選ぶ一覧文書。行間・余白を詰めてページ数を抑え、一覧性を上げる |

例：`python3 ...md2pdf.py "質問の見本帳.md" --compact`

- 出力は各mdの隣に同名`.pdf`。Driveマウント内に直接出力してよい（デスクトップ版Driveが自動同期する）。
- frontmatterはスクリプトが自動除去する。ただし**本文中に内部メモ**（「作成: Notion既存版より転記」等）が混ざっていないか、変換前にheadで一瞥する。見つけたら勝手に消さず、Mieyに確認する（外科的編集の原則）。
- 依存が無い環境なら：`python3 -c "import markdown"` で確認し、無ければ `pip3 install markdown`。Chromeは `/Applications/Google Chrome.app` 前提。

### 3. 仕上がりを目視で検証する

生成したPDFのうち**最低1冊の1ページ目をReadツールで開いて見る**（表の崩れ・日本語フォント・frontmatter混入がないか）。「生成できた＝正しい」ではない。確認できるまで完了と報告しない。

### 4. 報告する

- 生成したPDFの一覧（ファイル名＋配置先）
- 「Driveが自動同期するので数分でWeb側にも反映される」ことを添える
- 目視確認した1枚のスクリーンショット（Readの画像）が会話に出ている状態にする

## 注意

- 鑑定書は個人情報（生年月日・出生地）を含む。**公開の場所（Notion公開ページ等）には絶対に置かない**。配置先はそのお客様専用のDriveフォルダのみ。
- 新しいお客様のフォルダを新規作成する必要がある場合は、作る前にMieyに確認する。
- `obsidian_customer/` は `products/` や主リポジトリのgit管理外（`~/Documents/works/` 直下の独立ディレクトリ）。お客様の個人情報がGitHubへ誤って上がる心配はない構造だが、念のため他リポジトリへコピー・移設しない。
