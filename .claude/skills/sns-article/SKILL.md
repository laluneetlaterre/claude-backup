# sns-article スキル（SNS記事：診断・作成・媒体展開・サムネ）

## 役割（なぜ存在するか）

Miey は **ネタ・体験・文体**を自分で出せる（強み・自走領域）。このスキルの仕事は、その原石を受け取ってから投稿完了までの**パイプライン全部**：

```
ネタ → [D 診断・磨き込み] → [A 記事化(X版+note版…)] → [サムネ生成] → 投稿 → [C アーカイブ]
                                     ↑ [B 別媒体に展開]
```

どの段階から呼ばれてもよい。「診断だけ」「note版だけ」「サムネだけ」の単発も可。
＝ Miey は「命名？frontmatter？index更新？サムネのサイズ？」を気にせず、**中身を出すことだけに集中できる**。

文章の創造性は master `~/.claude/CLAUDE.md` §7 に従う。**文体・採否の最終判断は必ず Miey**。

---

## 絶対に守るガードレール（Miey ブランド保護）

インプを取るためにブランドを壊す改変は禁止。全モード共通。

1. **構造論軸を死守**。Miey のポジショニングは「事業継続・冗長性・unfair advantage・蓄積した知性」などの構造論。不安煽り・釣り・誇張に逃げない。個人ストーリー軸は現時点 NG（ファン基盤確立まで）。
2. **捏造は絶対禁止**。実績数字・エピソードは本人の実在のものだけ。実数がなければ `【ここに実数を】` と空欄で示す。
3. **文体・キャラは Miey のまま**（master §7.4）。AI 風に均さない。キャラ表記はタイトル/冒頭1〜2回まで。
4. **意味・主張を変える整形は黙ってやらず、草案として提案**（§7.3-3）。事実誤認は黙って直して1行報告（§7.3-1）。
5. **過剰ナレーション禁止**（master §4.2）。診断・成果物だけ出す。

トーン大方針は `~/Documents/works/obsidian/03_stock/02_IT_AIツール/ai-sns-post-kit.md`（「バズは殺さない・雑さだけ消す」）。

## 置き場所・命名・フォーマット（唯一の正）

- **置き場所**：`~/Documents/works/obsidian/02_sns-posts/articles/`
  - 作業中（下書き・推敲中）記事 … `articles/` 直下にフラット配置
  - **公開済み記事 … `articles/archived/`（一度でもSNSに投稿したら移動）**
  - ネタ・未作成の種 … `articles/_ideas/`
  - 画像・PDF・サムネ … `articles/_attachments/`（本文からは `![[ファイル名.png]]` で参照）
  - 一覧 … `articles/_index.md`（**作成・更新したら必ずここも更新**。「作業中」「アーカイブ」の2表に分かれている）
  - 発信戦略・分析は `02_sns-posts/_strategy/` `_analytics/`（articles の外・このスキルは触らない）
- **ファイル名**：`YYYY-MM-DD_トピック.md`（日付はネタ発生日 or 作成日）。**日本語OK・省略しない**（`…`や曖昧な短縮は禁止 / Miey は literally 動く）。日付が無い記事は日付プレフィックスなしの説明的な名前でよい。
- **frontmatter（必須）**：
  ```yaml
  ---
  type: sns-article
  topic: <トピック名・日本語可>
  status: ネタ / 下書き / 公開済み
  media: [x, note, cafetalk, threads, facebook, x-article]   # 展開した/する媒体
  created: YYYY-MM-DD
  posted: YYYY-MM-DD   # 初投稿日（アーカイブ送り時に記入）
  tags: [tag1, tag2]
  ---
  ```
  公開済みなら `published-note:` `published-x:` 等のURLも足してよい。
- **本文の構成**：媒体ごとに `## ○○版` 見出しで区切る。元ネタ・素材があれば先頭に `## 📌 マスター（元ネタ）`。
  ```
  ## 📌 マスター（元ネタ・素材）
  ## X版
  ## note版
  ## cafetalk版
  ## Threads版（500字ずつ・コピー用）
  ## Facebook版（md記号なし・コピー用）
  ```
- **note版には必ずハッシュタグを付ける**（Miey が note の投稿画面で毎回タグ欄に困るため）。note版セクションの末尾に `### ハッシュタグ（note用・コピペ）` を作り、`#タグ #タグ …` をスペース区切り1行で**そのままコピペできる形**で出す。記事内容に合わせて 8〜12 個。「リーチの大きい定番タグ（例 `#生成AI` `#ChatGPT` `#AI活用`）」＋「内容ピンポイントのタグ」を混ぜる。note のタグは日本語中心・公開用で、frontmatter の `tags:`（vault 内部検索用）とは別物なので混同しない。

## モード A：新規作成（ネタ→記事化）

トリガー例：「これ記事にして」「新しい記事作って」「○○を記事化」「このネタでX用とnote用作って」＋（ネタ・本文・1媒体版を貼る）。

1. トピック名・想定媒体・status を Miey の入力から決める（不明なら最小限だけ確認。根掘り葉掘り聞かない＝master §4.2）。媒体指定がなければ **X版＋note版** をデフォルトにする（Miey の主戦場）。
2. `articles/YYYY-MM-DD_トピック.md` を作成。frontmatter ＋ `## 📌 マスター（元ネタ）`（Miey のネタを原文のまま保存）＋ 各 `## ○○版` セクション。
   - **X版は「伸びる品質」で作る**：`references/growth-patterns.md` を読み、構文型（保存価値型／原則リスト型／発見型／短文×構造ビジュアル型が主軸）を選んで組む。140字目安、外部リンクは本文に入れない（リプライへ）。ネタが薄い・方向が複数あるときは、構文型ちがいの2〜3案を並記して Miey に選ばせる。
   - **note版は長文・保存向き**：見出し構造、具体例、ハッシュタグ（上記ルール）。X版の拡張ではなく note の読まれ方（検索・じっくり読み・保存）に合わせて組み直す。
   - まだ書きかけ・ネタ段階なら `articles/_ideas/` に置き status: ネタ。
3. `articles/_index.md` の表に1行追記。
4. 記事が形になったら **サムネイルを提案**（「サムネも作る？タイトル案：○○」と1行。下記「サムネイル生成」参照）。Miey が求めたら生成。
5. 作成後、**書けたか verify**（Read/grep で確認するまで「作成済み」と言わない）してから1〜2行で報告。

## モード B：媒体展開（既存記事に別媒体版を足す）

トリガー例：「note版作って」「cafetalk版作って」「Threads版にして」（対象記事を指すか、直近作業の記事）。

1. 対象の記事ファイルを特定（曖昧なら候補を出して確認）。
2. 既存の本文（マスター or 他媒体版）を素材に、**指定媒体に合わせて整形した `## ○○版` セクションを追記**する。
   - X の磨き込みは `references/growth-patterns.md` ＋ `~/Documents/works/obsidian/wiki/reference/x-post-editing-craft.md`。
   - 媒体の癖：X＝短文・フック／リンクはリプライ、note＝長文・保存向き・見出し構造＋ハッシュタグ、Threads＝500字ずつ連投、Facebook／cafetalk＝プレーン or HTML・コピー用（cafetalk HTML は絵文字NG等の制約 → memory `reference_cafetalk_html_constraints`）。
3. frontmatter の `media:` にその媒体を追加。`articles/_index.md` も更新。
4. verify → 1行報告。「最終文体は Miey が決めてね」を添える。

## モード C：アーカイブ（投稿後の片付け）

トリガー例：「投稿した」「公開した」「出した」「アーカイブして」（対象記事を指すか、直近作業の記事）。記事が**一度でもどこかのSNSに投稿されたら**実行。

1. 対象記事を特定。投稿した媒体・初投稿日を Miey の入力から取る（不明なら今日の日付を仮置きし1行で確認）。
2. frontmatter を更新：`status: 公開済み` ／ `posted: YYYY-MM-DD` ／ 投稿した媒体が `media:` に無ければ追加。
3. ファイルを `articles/archived/` へ**移動**（`mv`）。移動前にリンク整合性を確認（`[[ファイル名]]` 以外の相対リンク参照がないか grep）。
4. `articles/_index.md` を更新：「作業中」表から削除し「アーカイブ」表に追加（リンクは `./archived/ファイル名`）。各表末尾の件数も直す。
5. verify → 1行報告。

> 半分だけ投稿（例：X だけ出して note は下書き）の場合は一言確認。デフォルトは「主要媒体に1回でも出たらアーカイブ」。

## モード D：診断・磨き込み（旧 x-post-booster）

トリガー例：「この投稿伸ばして」「投稿診断して」「Xの叩き台みて」「バズる形にして」＋X投稿の下書き・ネタ。
**このモードはファイルを作らない**（チャットで完結）。診断結果を記事に反映したいときだけモード A/B につなぐ。

1. 貼られたものが「完成度のある叩き台」か「ネタ・断片」かを見極める。ネタだけならモード A 側で骨組みから（構文型を1〜2案提示）。
2. **7軸診断**を `○ / △ / ✕` ＋一言で（長文講評はしない）：
   ① フック（1行目で手が止まるか）② 具体性（数字・固有名詞・場面）③ 読みやすさ（改行・余白）④ 構造（リスト/対比/段階の型）⑤ ターゲット名指し ⑥ 感情トリガー（好奇心・発見・保存欲求。**不安煽りは使わない**）⑦ CTA・読後行動（保存/リポストしたくなる締め）
3. **改善版を2〜3案**。構文型は `references/growth-patterns.md` の「Miey 適用ガイド」から選ぶ。各案140字目安（スレッドなら各ツイート140字）。
4. 各案に「効く理由」を1行（なぜインプ/保存/リポストが伸びるか）。
5. Miey が選ぶ・直す。完了報告は最小限。

出力テンプレ：
```
【診断】
① フック：△ いきなり結論で手が止まらない
② 具体性：○ 数字あり
…（7軸、該当ある所だけでも可）

【改善案A：保存価値型】
（本文）
→ 効く理由：…

【改善案B：原則リスト型】
（本文）
→ 効く理由：…

採用するもの・直したい所を教えてください。文体は Miey のまま残しています。
```

アルゴリズムの狙い所（詳細は `references/growth-patterns.md`）：リプライ ＞ リポスト ＞ 保存 ＞ いいね。会話が生まれる・保存したくなる構造を優先。投稿後30分の初速が効くのでセルフリプライの余地を残す。

## サムネイル生成（ハイブリッド型：AI背景＋日本語タイトル合成）

日本語タイトルは AI 画像生成では崩れるため、**背景だけ Imagen で作り、文字は HTML で重ねて PNG 化**する2段構え。

トリガー例：「サムネ作って」「サムネイルも」「ヘッダー画像作って」、またはモード A の仕上げで Miey が求めたとき。

1. **タイトルと改行位置を決める**。記事の X版フック or note タイトルから短く（2行以内・1行14字目安）。`|` が改行。案が割れるなら1案だけ提示して確認。
2. **背景を Imagen で生成**（`mcp__vertex-ai__vertex_generate_image`）：
   - `model: imagen-4.0-generate-001` ／ `aspectRatio: "16:9"` ／ **`sampleCount: 1`（重要：省略すると4枚生成され課金が4倍になる）**
   - `saveToPath`: `~/Documents/works/obsidian/02_sns-posts/articles/_attachments/YYYY-MM-DD_トピック_bg.png`
   - プロンプトは英語で、記事テーマを抽象ビジュアル化。**必ず入れる**：`deep navy blue background, soft golden light accents, elegant, minimal, no text, no letters, empty space in the center for a title overlay`（ブランド配色＝深紺×金と、中央の文字スペース確保）
3. **合成**：
   ```bash
   python3 ~/.claude/skills/sns-article/scripts/make_thumbnail.py \
     --title "1行目|2行目" \
     --bg <背景png> \
     --out ~/Documents/works/obsidian/02_sns-posts/articles/_attachments/YYYY-MM-DD_トピック_thumb.png
   ```
   サイズはデフォルト 1280x670（note 推奨・X もこの比率でそのまま使える）。`--sub` でクレジット行変更可（デフォルト `Miey｜Obsidian × AI`）。
4. **記事に埋め込む**：該当記事の先頭（frontmatter 直後）に `![[YYYY-MM-DD_トピック_thumb.png]]` を追記。
5. 生成した PNG を Read で開いて**目視 verify**（文字切れ・背景との喧嘩がないか）→ Miey にパス付きで1行報告。気に入らなければ背景プロンプトかタイトル改行を変えて再生成。

急ぎ・背景不要のときは `--bg` なし（深紺グラデ背景）で即生成できる。

## やらないこと

- 勝手な公開・投稿（ドラフトを作るだけ。投稿は Miey）。
- Miey の文体を AI 風に均す／キャラ表現を本文で連発する（master §7.4・§4.1）。
- `_strategy/` `_analytics/`、cafetalk のレッスン・四柱推命・ポリシー等、articles 外の領域への変更。
- 既存セクションの指定外の書き換え（外科的編集の鉄則・他媒体版を勝手にいじらない）。
- ネタ出しそのもの・X分析データの取得（別作業。Miey の自走領域には介入しない）。
