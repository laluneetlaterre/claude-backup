Mieyからの2026-05-24指示：「TIPS統合 取り込みマップのファイルのところに、そのファイルのパスも書いてくれない？ 司令塔の会話でも、パスがないとわからない、検索しないとどれかわからないものも多くて、読み取りが大変」

**Why**:
- Vault内のファイル名は重複や類似が多く、ファイル名だけだと「どれの話？」と検索が必要になる
- Mieyは ADHD x HSP 傾向（[[user_neuro_profile]]）で、画面上の判断疲労を避ける必要がある
- 検索の手間 = 判断疲労の蓄積 = フォーカス喪失（[[feedback_phase_progression_lead]] と整合）
- Markdownリンク形式なら：① Obsidian/VS Code で**クリック1発で開ける**、② リンクのhref部分にパスが入っているのでホバーで確認できる、③ 表示文字列はファイル名で読みやすい
- Mieyの所感：「Claude codeを使っている他の皆さんは理解できるのかな？タイトル名で検索しているってこと？」→ つまり、これは Miey 固有の困りごとではなく、Claude Code を普通に使う人みんなが遭遇する問題。司令塔側でカバーすべき

**How to apply**:

1. **diary・MEMORY.md・チャット出力すべて**：ファイルに言及するときは必ず `[表示ラベル](相対パス/ファイル名.md)` 形式
2. **表示ラベルにフルファイル名を書かない**（2026-05-24 追加）：表示ラベルと href 末尾のファイル名が同一だと **視覚的に冗長**。表示ラベルは **内容を表す短いラベル**（`.md` 拡張子なし、アンダースコアは適度に外す）にする。
   - ❌ 悪い例：`[ターミナル基本コマンド完全リファレンス.md](path/.../ターミナル基本コマンド完全リファレンス.md)` ← ファイル名が2回出てくる
   - ✅ 良い例：`[ターミナル基本コマンド完全リファレンス](path/.../ターミナル基本コマンド完全リファレンス.md)` ← .md 削る／別キーワードに置換
   - ✅ もっと良い例：`[ターミナル基本コマンド](path/.../ターミナル基本コマンド完全リファレンス.md)` ← さらに短く
3. **ベースパスは省略しない**：絶対パスではなく、Obsidian Vault ルート（または lune ルート）からの相対パスを使う。例：`products/Claude Code + .../10_/04_商品関連ツール解説/obsidian-skills_導入と使い方.md`
4. **表示文字列はファイル名のみ**：パスを表示文字列に入れると表が崩れる。href部分にパスを入れて、表示は短く
4. **削除済みファイルは取り消し線**：`~~ファイル名~~`（リンクにしない、もう存在しないので）
5. **大量のファイルを表で並べるとき**：列に「ファイル」「パス」を分けるより、ファイル名をMarkdownリンクにする方が読みやすい
6. **VS Code/Obsidian 環境**：Markdownリンクのパスは相対パスで OK。両方クリック対応
7. **文書内の箇所を指すときは「ファイル＋見出し」まで（2026-06-18 追加）**：「方法A」「Step6」「あの表」のような部分名だけだと、どのファイルのどこか分からず Miey が探す羽目になる。`拡張編 §2「公式スキルを使う」の方法A` のように **ファイル名＋章タイトル（見出し）** まで添える。チャットでファイルを編集したと報告するときも同様。
8. **リンクがクリックで開けないことがある（2026-06-19 追加）**：パスに日本語・スペース・記号（`「」`・`+` 等）が多いと Markdown リンクが壊れ、Miey の環境（VS Code チャットパネル）でクリックしても開かないことがある。リンクは残しつつ、**確実な開き方を併記する**：「VS Code は `Cmd+P` → 『note販売』などファイル名の一部を入力」「Obsidian は `Cmd+O`」。ファイル名の一部だけで一意に絞れるよう、固有で打ちやすい名前を付けるとなお良い。Miey 2026-06-19「タイトルだけ書かれてもどこにあるか分からない、クリックしても開かない」。

9. **リンクの下に「フルパス行」を必ず添える（2026-08-09 追加・最重要）**：Miey 2026-08-09「パスもいつもわからないし、クリックしても開かないし、右クリックしてコピーして finder に貼り付けることもできない」。Markdown リンクは href が見えず・クリックが死んでいる環境では**役に立たない**。ファイルに言及したら、リンクとは別に **プレーンな絶対パスを 1 つの ``` フェンスに置く**（[[feedback_obsidian_code_block_one_click_copy]] と同じ一発コピー形式）。Miey は Finder で `Cmd+Shift+G` に貼れば飛べる。複数ファイルなら1フェンスに複数行。
10. **「開いて」と言われたら AI 側で開く（2026-08-09 追加）**：Finder で見せる＝`open -R "<絶対パス>"`（そのファイルが選択された状態で Finder が開く）。Obsidian で開く＝`open "obsidian://open?vault=Obsidian&file=<vault内相対パス（.md なし・URLエンコード）>"`（vault 名は `Obsidian`＝`~/Documents/works/obsidian`）。VSCode で開く＝`open -a "Visual Studio Code" "<絶対パス>"`。
11. **クリックが効かない真の原因＝日本語パス（2026-08-09 確定・Miey が実クリックで検証済み）**：詳細は [[feedback_ascii_paths_for_clickable_links]]。**パス全体が ASCII のリンクだけがクリックで開く**。日本語・スペースが1文字でも入ると、描画時に percent-encode されたまま解決されず無反応になる。よって：
    - ASCII のみのパス → 普通に Markdown リンクにする（**ちゃんと開く**）
    - 日本語・スペース入りのパス → **リンクにしない**。バッククォートのプレーンパス＋フルパス行で書く（死んだリンクは「クリックできるはず」と誤解させるぶん無い方がマシ）
    - `file://` `vscode://` `obsidian://` を Markdown リンクにしても**必ず死ぬ**（http/https/mailto 以外は href が空にされる仕様）。二度と試さない。
    - なお「マルチルートのワークスペースが原因」という当初の推測は**誤り**だった（2026-08-09 に反証済み）。再検討しないこと。

**例（良い）**：
```
| [obsidian-skills 導入と使い方.md](products/.../obsidian-skills_導入と使い方.md) |
```

**例（悪い）**：
```
| obsidian-skills 導入と使い方 |  ← ファイル名だけ、検索が必要
```

**判別基準**：チャットや diary で「○○というファイル」と書いたら、自動でリンク化されているか確認する。されていなければ即修正。
