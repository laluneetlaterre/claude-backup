確認質問は OK（クレジット節約のため、勝手に動くより聞く方が良いケースは多い）。ただし、**質問する前に、memory / grep / 既知のフォルダ構造から拾える文脈はまず拾ってから聞く**。把握している文脈を1行示してから「これで合ってる？」と確認する形にする。

**Why:** 2026-05-31、Obsidian 構築商品のセットアップ検証作業中、Miey から「別冊セットアップガイドと本文がどこにあるか」を聞いたところ、Miey から「司令塔はわかってるんじゃないの？」と指摘された。memory には [本文_AI第二の脳システム_v0 はマスター素材](feedback_obsidian_book_master_source.md) と書かれており、`products/Claude Code + Obsidian.../10_第二の脳セットアップ.../` の場所はほぼ特定できていたはずだった。司令塔が「次から先に grep する」と謝罪したら、Miey から「いやそれでクレジット使うんだったら聞いてくれてもいいけど、文脈わかってないのかなと不安になるよ（笑」とフォロー。つまり「黙って探せ」ではなく「文脈持ってから聞け」が正解。

**How to apply:**
- 質問前に必ず：(a) memory を読む、(b) ファイル名・パスから推測できることはする、(c) 関連 grep を1〜2回打つ ── の最低限の文脈拾いをする
- 聞き方の型：「memory に〇〇とあったので、ファイルは `products/xxx/...` 配下にあると思うが、正確なパス教えて」
- ✘ NG：「ガイドの場所教えて」「本文どこ？」（文脈ゼロ）
- ✓ OK：「memory の `本文_AI第二の脳システム_v0 はマスター素材` から推測すると `products/Claude Code + Obsidian.../` 配下と思うが、具体ファイル名は `本文_AI第二の脳システム_v0.md` で合ってる？」
- クレジット節約と文脈把握はトレードオフではなく両立可能。文脈拾いは grep 1〜2回程度で済むことが多い
