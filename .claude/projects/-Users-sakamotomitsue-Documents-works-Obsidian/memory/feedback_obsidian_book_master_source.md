**本文_AI第二の脳システム_v0.md は派生展開のマスター素材。** YouTube 台本・LP・note・セミナー告知・X スレッドへの切り出し元になることを前提に書く。各章はそれ単独で派生先に切り出せる構造単位で書き、汎用性を維持する。

**Why:** 2026-05-30、第1章 opener をコピー素材 F1（ペイン → reframe → メカニズム → ソリューション）構造に差し替えた直後、Miey から「Youtube 台本にもそのまま流用できるレベル」「派生できる基本中の基本の本文が出来上がってきていて嬉しい」と評価。汎用化＋構造化を維持できれば派生コスト（弁護士版・コンサル版・不動産投資家版・医師版・起業家版、加えて YouTube 台本・LP・note）が激減する戦略的価値が確認された。frontmatter にも `positioning: 営業色なし汎用版（...4種類のお客様＋ Miey 自身の勉強リファレンスをすべて兼ねる）` と明記されている。

**How to apply:**
1. **本文の各章は、それ単独で派生先に切り出せる構造単位で書く**。章内で完結する構造（問題提起 → 説明 → 要点）を保つ。章をまたぐ参照は最小化。
2. **Miey 個人データ・案件固有データは本文に入れない**（実ファイルパス・`lune` 等の固有名詞・Miey の運用詳細）。誰の環境でもそのまま使える汎用記述に統一。
3. **識別フック（「できる人」等）・商品接続（「セミナーでは」「弊社の構築サービス」等）は本文には入れない**。これらは [[feedback-obsidian-construction-sales-copy]] のコピー素材ファイル（`コピー素材_unfair_advantage_フレーム.md`）側で管理する切り分けを維持。本文は構造（ペイン → reframe → メカニズム → ソリューション）だけ採用。
4. **「営業色なし＋ Miey も使える勉強リファレンス」要件を常に満たす**。これにより構築サービスのお客様・30万円契約者・初心者・Miey 自身、すべてが同じ本文を読める。
5. 派生展開時はこの本文を母艦として、派生先固有の差分（動画用フック・LP のセールスフロー・X の文字数制約）だけを別ファイルに切り出す形を取る。
