Mieyからの2026-05-24指示：「私のようなADHDはこのように情報が散らばっていると、気になって前に進めないので、情報がごちゃごちゃしているものがあったら整理を提案してね」

**Why**:
- Miey は ADHD x HSP 傾向（[[user_neuro_profile]]）で、視界の中の散らかりが認知リソースを奪い、本来やりたい作業に集中できなくなる
- 散らばりは「気になる → でも整理は判断疲労 → 結果動けない」のパターンに直結
- 司令塔が能動的に発見・提案することで、Miey の脳のキャパを作業実行に温存できる（[[feedback_phase_progression_lead]] と同じ思想）
- 2026-05-24 に sns-posts/ 整理で実証：「ダブル司令塔事件」関連が3箇所に散らばっていた件を司令塔から提案 → Miey 即GO で集約完了

**How to apply**:

1. **能動スキャンの義務**：作業中に同じテーマ（SNS発信、商品素材、戦略メモ、特定プロジェクト等）の情報を複数の場所で見たら、その瞬間に「散らばってます、集約案出します」と司令塔から声をかける。Mieyに気づかれるのを待たない。

2. **集約案は1本に絞る**：[[feedback_phase_progression_lead]] と同じく、選択肢を並べない。司令塔の推奨案（移動マップ・新フォルダ構成・ファイル名規則）を1案だけ提示し、Miey は GO/STOP だけ判断。

3. **スキャンは欲張らない**：1テーマずつ。「SNSも商品も lune も全部一気に」とやると Mieyの認知リソースを逆に奪う。テーマ単位で完結させる。

4. **「全部集めた？」への備え**：Miey は提案を受けたとき「他に同じテーマで散らばってないか？」を確認する癖がある。提案前に vault 全体を `find`/`grep` で1回スキャンして、見つかった候補は全部リスト化してから提案する（同一テーマで2回目の整理を発生させない）。

5. **Rule 3 遵守**：5ファイル以上の移動・フォルダ新設・削除は必ず Miey の明示 GO を取る。memory の「能動提案ルール」があっても、実行はGOの後。

6. **整理対象の判定基準**：
   - 「同じ用途で使うものが複数フォルダに散らばっている」→ 集約候補
   - 「探索プロセスのログ（壁打ちログ等）」→ stock に残す（確定メモではないため）
   - 「他人の素材クリッピング」→ clippings/notion に残す（Mieyの発信原稿ではない）
   - 「Claude Code のスキル/エージェント定義」→ skills/agents に残す（運用機能のため）

**実例リファレンス**：2026-05-24 sns-posts/ 整理（このルール初実施）。整理後の構成は `sns-posts/{x,note}/` `sns-posts/{_strategy,_ideas,_analytics}/` で確定。次回の整理提案時はこの構造を踏襲。
